# Optimal trajectory solver

Численный пример перелёта в центральном гравитационном поле: одиночная стрельба и адаптивное продолжение по весу смешанного функционала от α=0 до α=1.

Рабочая модель: безразмерные координаты, μ=1, фиксированное время и граничные состояния; управление — ускорение. По умолчанию `a_max` подбирается вместе с начальными сопряжёнными переменными. Достигнутая малая краевая невязка не является доказательством локального или глобального минимума. Исследовательское развитие описано в [отдельной постановке](pazov_geometry_research_proposal.md); двумерный атлас и псевдодуговое продолжение пока не реализованы.

## Установка

Проверено на Windows, Python 3.11.5. Версии четырёх прямых зависимостей зафиксированы в `requirements.txt`; версии окружения также записываются для каждого запуска. Транзитивные зависимости не зафиксированы, побитовое совпадение между разными платформами не гарантируется.

Из корня проекта в PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активация окружения не требуется. В примерах ниже `python` означает интерпретатор подготовленного окружения; в PowerShell можно использовать `.\.venv\Scripts\python.exe`.

## Запуск

```powershell
python run_continuation.py
```

Результат появится в новой папке `outputs/<дата-время>/` внутри проекта. Можно выбрать другую **ещё не существующую** папку:

```powershell
python run_continuation.py --output outputs/my-run
```

Повторное использование существующей папки запрещено, чтобы результаты разных запусков не смешивались. Скрипты можно вызывать и из другой рабочей директории; относительный `--output` считается от неё. Без `--output` результат всегда сохраняется внутри проекта. Импорт модулей не запускает расчёт.

Параметры штатного примера находятся в `run_continuation.py`: λ=0,5 оборота, отношение радиусов κ=1,5; α от 0 до 1; допуск полной краевой невязки 0,01; обычный шаг от 0,0001 до 0,2. При неудаче на обычном минимуме нижний предел локально снижается до 0,00001; после восстановления размера шага возвращается обычный предел. Интегрирование: LSODA, `rtol=1e-9`, `atol=1e-12`. Корректор по умолчанию использует выбранный профиль `diff5_tight`: `least_squares`, TRF, `jac='2-point'`, относительный шаг Якобиана `diff_step=1e-5`, `x_scale=1`, `xtol=ftol=gtol=1e-10`, максимум 200 оценок по настройке `max_nfev`. Профиль применяется к ограниченным коррекциям; начальное неограниченное квадратичное уточнение сохраняет исходные настройки. Основания выбора и проверки на 11 геометриях — в [отчёте подбора](diagnostics/HYPERPARAMETER_TUNING_2026-10-22.md).

Автоматический старт использует `get_initial_adjoint(lambda_value, kappa)` для фактической задачи. λ задаётся явно в оборотах через `set_boundary_conditions(..., lambda_value=...)`; κ вычисляется как отношение норм конечного и начального радиус-векторов. Число полных оборотов нельзя однозначно восстановить из конечных координат, поэтому при отсутствии λ нужно передать собственное `p0_guess`/`p0_initial`. Переданное пользователем приближение имеет приоритет при выборе начальных сопряжённых переменных.

При α=0 и свободном `a_max` сначала уточняется квадратичное решение **без ограничения тяги**, по шести сопряжённым переменным. Затем `a_max` задаётся равным численному максимуму `|p_v(t)|` на всей полученной траектории, без запаса; внутренние максимумы уточняются по непрерывному выходу интегратора. Сохраняется нижняя граница `1e-4`. Если максимум превышает существующую верхнюю границу 1, начальное решение отклоняется, а не обрезается. Седьмой компонент переданного приближения не ограничивает этот начальный расчёт. Проверяется повторное интегрирование с выбранным ограничением: краевая невязка должна укладываться в заданный допуск, а максимальное отклонение шестикомпонентного состояния от неограниченного решения — в `1e-7`. Это численная проверка, а не строгое доказательство максимума. Далее `a_max` снова корректируется вместе с сопряжёнными переменными. При `free_a_max=False` заданное ограничение сохраняется и этот способ инициализации не применяется.

Аппроксимации старта рассчитаны для нормированной модельной геометрии проекта (μ=1, начальный радиус вдоль x, движение против часовой стрелки); автоматическое преобразование произвольной системы координат и иных единиц не реализовано. Для таких задач передавайте проверенное начальное приближение.

В `continuation_method` параметр `h_min` задаёт обычный нижний предел, а `h_min_floor` — окончательный. По умолчанию окончательный предел равен `h_min/10`. Установка `h_min_floor=h_min` отключает локальное снижение. После неудачи на обычном минимуме шаг сначала делится пополам, а не сразу прыгает к самому мелкому значению. События снижения и восстановления сохраняются в `step_floor_history` и сводке запуска.

Время зависит от окружения и пути корректора. После применения выбранного профиля штатный пример на i9-13900KF, Python 3.11.5 достиг α=1 за 21,16 с: 11 решений, 14 попыток. Это отдельный контрольный замер, а не гарантированное время. Актуальное время каждого запуска записывается в `summary.json`.

## Результаты и статусы

- `summary.json`: статус, целевое и достигнутое α, параметры задачи, профиль и параметры корректора (`corrector`), невязка последнего решения, время, версии библиотек, Git-коммит и SHA-256 Python-исходников. Также содержит параметры автоматического приближения, проверку начального квадратичного решения (`initial_quadratic`) и историю локального изменения нижнего предела шага. Хеши отражают и незакоммиченные изменения.
- `run.log`: журнал корректора и сообщения об отказах.
- `step_vs_alpha_data.csv`: все попытки продолжения; `success=1` только для принятых решений.
- `solutions.npz`: все принятые решения. Массивы `alpha`, `a_max`, `p0`; для решения с индексом `i` — `t_i` и `y_i`. Строки `y_i`: `r[0:3]`, `v[3:6]`, `p_r[6:9]`, `p_v[9:12]`.
- `alpha1.pkl` и `earth_mars_alpha1.png` создаются только при достижении α=1.
- При частичном расчёте вместо них сохраняются `partial_solution.pkl` и `earth_mars_partial_solution.png` с фактическим α.
- `thrust_profiles.png`, `h_vs_alpha_plot.png`, `active_segments.txt`, `passive_segments.txt`: графики и координаты участков. Текстовые массивы содержат объединённые точки соответствующего типа, без времён и границ между отдельными дугами.

Коды завершения: **0** — `completed`, цель достигнута; **2** — `partial`, сохранены принятые решения, но цель не достигнута; **1** — начальное решение не принято (`initial_failed`) либо произошла ошибка (`failed`). При начальном отказе сохраняются сводка, журнал и CSV, но файл решения не создаётся. Ошибка аргументов командной строки также имеет стандартный код 2 — её отличает сообщение о неверном вызове.

Успех оптимизатора сам по себе не достаточен: принятое решение должно успешно интегрироваться до конечного времени, иметь конечные значения и краевую невязку в пределах допуска. При ранней остановке статус не интерпретируется как отсутствие ветви или недостижимость задачи.

Для чтения численных данных без запуска решателя:

```python
import numpy as np
with np.load('outputs/my-run/solutions.npz') as data:
    print(data['alpha'], data['a_max'])
    t, y = data['t_0'], data['y_0']
```

## Повторное построение

```powershell
python graph.py outputs/my-run/step_vs_alpha_data.csv
python plot_from_pickle.py outputs/my-run/alpha1.pkl
```

Оба скрипта принимают `--output путь.png`; по умолчанию записывают рисунок рядом с выбранным входным файлом. Второй скрипт также записывает туда массивы участков. Для частичного решения передайте `partial_solution.pkl`. Загружайте через pickle только доверенные файлы: формат допускает исполнение кода при чтении. Для анализа собственных сохранённых массивов используйте `solutions.npz`.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Быстрые регрессионные проверки охватывают отказы интегрирования, неприемлемое начальное решение, пустое и частичное продолжение, имена выходных файлов, радиусы орбит и индивидуальное ограничение тяги на графиках. Полный численный прогон выполняется отдельно штатной командой запуска.

Эти же быстрые проверки настроены в GitHub Actions на Python 3.11 при push и pull request. Настройка добавлена в репозиторий; выполнение на GitHub требует публикации изменений.

## Состав проекта

- `solver.py`: динамика, управление, стрельба, продолжение, графики и сохранение.
- `approximations.py`: исходные аппроксимации времени и сопряжённых переменных.
- `run_continuation.py`: штатный пример и изолированное сохранение результатов.
- `graph.py`, `plot_from_pickle.py`: вспомогательные команды.
- `tests/`: регрессионные проверки.
- `Theory.pdf`, `tezisy_Pazov.docx`, исследовательская постановка: материалы проекта.

Старые графики, CSV, текстовые массивы и `alpha1.pkl` в корне — исторические файлы репозитория, а не результат нового запуска. Новые результаты находятся в `outputs/` и не включаются в Git. Существующие исторические материалы сохранены. Скомпилированные `.pyc` исключены из отслеживания; исходный `.py` остаётся источником программы.
