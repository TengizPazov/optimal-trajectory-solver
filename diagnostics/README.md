# Проверки устойчивости

Этот каталог содержит диагностическую обвязку; `solver.py`, формулы управления, корректор и алгоритм продолжения она не меняет.

Обозначения: λ — угловая дальность в оборотах; θ=2πλ. В аппроксимациях λ передаётся как аргумент `a`. κ — отношение радиусов. Для каждого случая задаются согласованные конечные положение и круговая скорость, а время вычисляется как `2π T_a(λ,κ)` и затем фиксируется. Это прикладная генерация тестовых задач, а не проверка области применимости исходных аппроксимаций по первоисточникам.

## Серии

- `initial_plan.json`: 13 разбросанных геометрий, каждая со штатным и согласованным с λ, κ начальным приближением. Только начальная задача α=0.
- `full_plan.json`: выбранные проходы до α=1, включая κ около 1 и 1,5, контроль известного стыка λ=0,75, сравнение точных нулей и `sin(π)` в границах, а также мелкий шаг по α.
- `strict_plan.json`: две задачи около κ=1 с допуском `1e-5` вместо `0.01`.
- `local_lambda_plan.json`: λ=0,4999 и 0,5001 при κ=1,5.
- `window_plan.json`, `window_control_plan.json`: короткое окно α≈0,531–0,532 из одного сохранённого решения, для сравнения `h_min` и начального шага. Требуют предварительного результата `strict_plan.json` по пути `seed_from`.

`default` воспроизводит исторический контроль D1: явно передаёт старое приближение для λ=0,5 и κ=1,2 независимо от фактической задачи. `auto` использует исправленный автоматический старт производственного решателя для фактических λ и κ, с проекцией начального A в границы. `matched` явно передаёт аппроксимацию для фактических λ, κ, добавляя начальное `a_max=max(|p_v|,0.1)`. `matched_capped` дополнительно ограничивает эту оценку единицей. При свободном `A` разные старты не обязаны выбирать одну экстремаль. В старых планах явно закреплён `h_min_floor=h_min`, чтобы воспроизводить прежний фиксированный нижний предел.

Планы `d1_d3_*_plan.json` повторяют проблемные случаи после исправления D1 и D3. Они используют `auto` и локальное снижение нижнего предела шага; контроль короткого окна выполняется из одного сохранённого решения с включённым и отключённым снижением. λ=0,75 и окрестность этого стыка в повторную серию не включены.

Результаты повторной серии: [D1_D3_FIX_VALIDATION_2026-10-22.md](D1_D3_FIX_VALIDATION_2026-10-22.md). Исправления локально подтверждены; оставшиеся таймауты и ухудшение времени базового примера отмечены отдельно.

Применение начальной аппроксимации и парная трассировка старого/нового старта: [BASE_START_APPLICATION_AUDIT_2026-10-22.md](BASE_START_APPLICATION_AUDIT_2026-10-22.md). Проверены исходные формулы автора, единицы, начальные невязки и причины отказов корректора; код решателя в этом разборе не менялся.

После этого начальный свободный A стал задаваться по максимуму тяги уточнённого неограниченного квадратичного решения: [QUADRATIC_INITIAL_CAP_2026-10-22.md](QUADRATIC_INITIAL_CAP_2026-10-22.md). Поэтому перечисленные выше варианты старта при α=0 теперь проходят этот общий этап; их прежние сохранённые результаты относятся к указанным в них версиям решателя.

Полный базовый проход с новым начальным A без общего лимита времени достиг α=1 за 1043,54 с: [BASE_FULL_QUADRATIC_2026-10-22.md](BASE_FULL_QUADRATIC_2026-10-22.md). Здесь конкретизирована D4: поздние коррекции многократно исчерпывают max_nfev при уже малой невязке. Сохранены все попытки и выполнена независимая проверка всех принятых решений.

Подбор гиперпараметров: [HYPERPARAMETER_TUNING_2026-10-22.md](HYPERPARAMETER_TUNING_2026-10-22.md). 49 запусков, 10 профилей и 11 геометрий; λ=0,75 исключено. Выбран относительный шаг Якобиана `diff_step=1e-5` при исходных остальных настройках. Профиль сохранён в `tuned_corrector_profile.json`, план его повторения — в `tuned_cases_plan.json`. По последующему поручению пользователя профиль применён по умолчанию; штатный пример прошёл за 21,16 с. Диагностическая обвязка явно сохраняет прежний базовый шаг разностей для контрольных профилей, чтобы планы подбора оставались воспроизводимыми после смены штатных настроек. Подробные данные подбора собирает `summarize_tuning.py`.

## Повторение

Из корня проекта, в окружении из основного README:

```powershell
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/initial_plan.json --output outputs/stability-initial-2026-10-22 --jobs 4 --timeout 90
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/full_plan.json --output outputs/stability-full-2026-10-22 --jobs 4 --timeout 180
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/strict_plan.json --output outputs/stability-strict-2026-10-22 --jobs 2 --timeout 180
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/local_lambda_plan.json --output outputs/stability-local-lambda-2026-10-22 --jobs 2 --timeout 180
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/window_plan.json --output outputs/stability-window-2026-10-22 --jobs 2 --timeout 90
python -X utf8 -B diagnostics/stability_sweep.py --plan diagnostics/window_control_plan.json --output outputs/stability-window-control-2026-10-22 --jobs 1 --timeout 90
```

Все выходные каталоги должны быть новыми. Для повторения в том же checkout выберите другие имена; также измените `seed_from` в планах короткого окна. Сохранённые копии планов внутри результатов фиксируют фактическую конфигурацию запуска.

Каждая задача выполняется в отдельном процессе: LSODA не вызывается одновременно из нескольких потоков одного процесса. Потоки BLAS ограничены единицей. Часть серий выполнялась одновременно; времена служат диагностикой затрат, а не изолированным сравнительным бенчмарком.

`--timeout` ограничивает время процесса вместе с импортом и проверками. `elapsed_seconds` завершённых случаев измеряется внутри рабочего процесса. Остановка по времени не означает несходимость при неограниченном бюджете. В ранних остановленных случаях есть только последний **попытанный** α, а не подтверждённая точка; это поле нельзя выдавать за достигнутый α. В более поздних запусках дополнительно сохраняется последняя принятая траектория `last_accepted.npz` с параметрами в `last_accepted.json`.

В каждом завершённом случае сохраняются JSON с показателями, журнал и NPZ всех принятых решений. Для последней принятой траектории выполняется независимое прямое интегрирование DOP853 при тех же начальных сопряжённых переменных и `A`, с `rtol=1e-10`, `atol=1e-12`, `max_step=T/200`. Это проверка интегрирования, без повторной оптимизации и без доказательства оптимальности.

`Q` и `L` оценены методом трапеций на адаптивной сетке и служат диагностическими величинами. Число активных дуг определяется тем же порогом, что в текущей визуализации; это не локализованные события. Развёрнутый угол вычисляется по узлам интегрирования и также не является доказательством принадлежности ветви.

Сбор общей таблицы:

```powershell
python -X utf8 -B diagnostics/summarize_stability.py outputs/stability-initial-2026-10-22 outputs/stability-full-2026-10-22 outputs/stability-strict-2026-10-22 outputs/stability-local-lambda-2026-10-22 outputs/stability-window-2026-10-22 outputs/stability-window-control-2026-10-22 --output outputs/stability-report-2026-10-22/results.csv
```

Итоговый разбор проведённой серии: [STABILITY_REPORT_2026-10-22.md](STABILITY_REPORT_2026-10-22.md). Стык λ=0,75 включён как известная проблема, а не как новое наблюдение. Исследовательские выводы о геометрии ветвей этими тестами не устанавливаются.
